## Outcome

This checkpoint removes the first confirmed source-integrity defect: Tirion no
longer equates a configured Claude OTLP trace exporter with a trace-capable
runtime. It manages and checks Claude's enhanced-telemetry gate, explicitly
closes assistant-response logging, and treats the non-blockable `StopFailure`
hook as part of the exact managed lifecycle source shape.

It also accepts one narrow, pinned terminal-failure fact. With exact requested
model `claude-sonnet-5` and a synthetic invalid first-party API key, Claude Code
2.1.201 emitted one matching `StopFailure(authentication_failed)`, no `Stop`,
two failed `401` requests, and one closed interaction. Tirion now correlates that
hook to the remembered opaque prompt/session, emits one idempotent failed
terminal occurrence, and publishes optional provider-neutral
`run.ended.outcome: "failure"` while lifecycle `state` remains `completed`.
The accepted snapshot contained a second, auxiliary Haiku title request;
repeated pinned runs show that trace child is optional. Native census acceptance
therefore requires one failed requested-model span and permits zero or one
failed Haiku title span. Production terminal authorization does not depend on
that span count; it depends on the exactly matched submission and failure hook.

After explicit operator re-authentication and an upgrade to Claude Code 2.1.207,
the metadata-only census completed seven successful-model scenarios plus one
blocked/final Stop scenario and one background-paused Stop scenario. A later
fixed-binary acceptance then exercised real Claude Code 2.1.207 with exact
requested model `claude-sonnet-5` through Tirion's managed source, durable
classification/projection, and outbound webhook path for one read-only root and
two writing roots. The full harness passed with 41 deliveries and no queued or
blocked events.

fixture suite had missed: a same-request Claude OTLP wrapper re-promoted a
nonzero Bash hook from honest `unknown` to `success`; provider prompt logs from
closing old CLI sessions published one start-only ghost root; and independent
review found that post-completion evidence and child-stop revisions needed
stronger authority boundaries. The fixes now keep every Claude shell
hook/log/trace copy fail-closed without explicit process outcome, require
human/typed transcript provenance on the `submission_hook` for public Claude
starts, freeze only explicit provider
completion while keeping inactivity revisable, and retain `SubagentStop` as an
unknown stop attempt until exact child closure exists.

## Construct Decision

No new construct was added. The implemented behavior improves existing jobs:

- `TelemetrySourceConfiguration` owns enhanced trace enablement, Claude's
  native trace-export interval plus the compatible generic batch delay, explicit
  content gates, exact lifecycle hooks, drift detection, and restore.
- `TelemetryIngress` owns transient content-bearing hook receipt, reads only a
  bounded race-checked tail under the resolved Claude `projects` root, and
  reduces accepted or ignored lifecycle provenance to privacy-safe diagnostics.
- `PrivacyGuard` remains the only boundary allowed to turn provider payloads
  into durable observations. It resolves only human/typed or
  task-notification/system Claude transcript provenance; unavailable or
  ambiguous production provenance fails closed.
- `RunCorrelationLedger` retains the proven failure outcome and allowlisted
  category monotonically. Its Claude lifecycle state is query-scoped: an active
  session entry is only a routing pointer, completed aliases cannot reopen, and
  sequential prompts release only their own terminal halves. An active
  submission hook outranks delayed provider telemetry; background pause handling
  suppresses a physical close only through exact trace-to-native-prompt identity.
  Raw/transcript aliases are atomic and conflict-closed. A background Stop's
  query remains the generated-task target across completion and a newer manual
  prompt until that newer query's own background Stop replaces it.
- `TelemetryClassification` accepts the fixture-backed failure boundary and the
  bounded native root identity, Stop-candidate, closed-interaction, and exact
  session-title-purpose joins exercised by the current full-stack acceptance.
  It also owns fail-closed Claude shell-copy semantics and nonterminal
  `SubagentStop` attempts. For direct Agent lineage it transiently hashes exact
  response child identity, bridges it to exact `SubagentStart`, discards all
  other response/input content, uses exact `tool_use_id` ownership, and fails
  closed through bounded parent-first trace and same-request-owner ledgers.
- `UsageProjection` and `ExternalWebhookDispatch` carry that provider-neutral
  outcome without inventing success for ordinary `Stop`; they also exclude
  exact auxiliary session-title purpose from customer projection and live
  lifecycle snapshots while preserving unclassified usage. Explicit completion
  fixes the accounting boundary, and Claude public starts require the managed
  human/typed submission hook. Child hook/tool/trace copies are joined by whole
  connected components; every non-conflicting member ID stays an ownership
  alias, exact child lifecycle owns semantic timing/outcome, and an Agent launch
  without exact closure remains open and unknown. Webhook delivery coalesces
  per-run work, prioritizes terminal meaning, and reconciles concurrent updates
  against the durable delivered high-water with content-derived event IDs and
  strict logical `updatedAt` ordering. Terminal admission is a dedicated
  projection path: it never awaits outbound HTTP, immediately projects a Claude
  query family after the exact Stop/closed-root join, and durably queues an
  eligible terminal even while a same-run update attempt is in flight. It does
  not make same-run HTTP attempts concurrent. Lifecycle sequences describe
  receiver-visible deliveries, not every queued row: successful terminal
  delivery suppresses pending stale running snapshots. Normal completed delivery
  remains `run.start -> delivered run.update(s) -> run.ended`, retaining an
  eligible settling update before terminal. The sole exception is the trusted
  Claude closed-root terminal whose webhook `codingHarness` and runtime are
  `claude-code`, whose `evidence.basis` is `root_span`, and whose
  `evidence.delayed` is `false`: when fresh and due, it ranks after fresh starts
  and ahead of fresh settling rows from the same or another run in ordinary and
  bounded-bypass lifecycle selection. Its public sequence is
  `run.start -> optional delivered run.update(s) -> run.ended`. An update
  already in flight completes first. A terminal failure/retry leaves the
  same-run settling row as a fallback; successful terminal delivery suppresses
  it. This narrow priority rule is implemented and deterministically verified,
  not live readiness. The bounded lifecycle-anchor delivery claim may still
  bypass one unrelated ordinary response in flight. Update and terminal cost
  selection follows the chosen token totals so expanded partial-cost meaning
  cannot inherit an older smaller snapshot's `complete` coverage.
- `Diagnostics` continues to emit only privacy-safe metadata. Live audits can
  now read an inclusive UTC window from the active private structured log and
  three bounded rotations, with the returned surface still capped at 1,000
  events.

## Why Classification Stopped Here

The pre-existing native probe scripts were audited and found unsuitable as
regression evidence because they persist raw OTLP bodies, request headers, CLI
stdout/stderr, and content-bearing samples. Claude telemetry can also carry
account, email, organization, command, tool-input, path, prompt, and response
data. Running those probes successfully would violate the program's evidence
handling rules even if their output were later deleted.

The replacement census reduces payloads in memory, aliases opaque IDs, preserves
only allowlisted numeric/enumerated metadata and trace topology, never writes raw
payloads or headers, and runs deterministic adversarial privacy tests in
`npm run check`. The successful 2.1.207 matrix used preflighted first-party Pro
auth without copying credentials or invoking login automatically.

The census also requires request-local scenario/event headers, immutable
PreToolUse approval tuples, and independent disposable-repository verification.
Its manifest still keeps `telemetryGateEffectObserved: false`: successful model
execution and absent canaries do not by themselves prove every requested content
gate dynamically.

That infrastructure allowed `CC-13` to move into production classification and
now supplies safe 2.1.207 evidence for the successful, blocked-Stop, and
background-paused scenarios. The fixed-binary run additionally accepts bounded
root identity, completion, exact title exclusion, writer cost, causal file, and
webhook behavior. The interactive nonzero-Bash rerun additionally accepts the
bounded shell-outcome/start-authority slice. The failed `CC-06`, `CC-06-R`, and
`CC-06-RR` runs drove deterministic query-lifecycle, transcript-provenance
ordering, direct Agent bridge, exact owner/alias, honest coverage, and
webhook-concurrency repairs. `CC-06-RRR` accepted that bounded core live, then
exposed provider-neutral update-order, cross-run delivery, and diagnostic-
retention barriers. `CC06B` rebuilt and verified the strict update clock and
diagnostic-window subset, but not the requested one-message batch or cross-run
bypass. Recursive/nested lineage, child-first ordering, restart/eviction behavior,
skill-token meaning, MCP, workflow/team behavior, restart-spanning native joins,
interruptions, retry exhaustion, and other interactive behavior still require
their own native evidence and deterministic tests at the owning construct.
